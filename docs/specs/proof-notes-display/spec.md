## Objective

The proof worksheet (`scripts/proof_worksheet.py`) displays a "Facilitation"
section per slide showing the speaker notes from `<deck-slug>-notes.json`, so
the presenter can review and refine facilitation intent during the Step 4.5
loop before any LLM render cost. The notes appear after the card table and
before the art-direction section, HTML-escaped for safety.

## Boundaries

### Always do

- HTML-escape all notes text before inserting into HTML output (use the
  existing `esc()` helper).
- Keep `render_worksheet()` backwards-compatible: `notes_by_slide` is an
  optional parameter with default `None`.
- Load notes.json from `deck_dir / f"{deck_dir.name}-notes.json"` only if
  the file exists; silently skip if absent.

### Ask first

- Any change to the layout position of the Facilitation section
  (currently: after card table, before `<details class="aux">`).
- Any addition of CSS classes to `assets/proof/proof.css` that affect
  non-Facilitation elements.

### Never do

- Display an empty Facilitation row (no placeholder, no "no notes" text).
- Add new Python dependencies.
- Touch `html_packager.py`, the Preview HTML, or any render pipeline script.
- Change the `render_worksheet()` positional parameter order for `deck_dir`,
  `pages`, `as_of`.

## Testing Strategy

- **TDD** for `render_page()` with and without notes — test that the Facilitation
  section appears when notes are provided and is absent when not. Tests in
  `tests/test_proof_worksheet.py`.
- **TDD** for HTML escaping — inject `<script>alert(1)</script>` in notes text;
  confirm `<script>` does not appear unescaped in output.
- **Goal-based check** for `build()` loading notes.json and passing to
  `render_worksheet()` — verified by checking that the Facilitation content
  appears in the `build()` output HTML.
- **Goal-based check** for determinism — render twice with the same notes.json;
  output must be byte-identical.

## Acceptance Criteria

- [x] `render_worksheet(deck_dir, pages, as_of, notes_by_slide=None)` accepts
  an optional fourth parameter `notes_by_slide: dict[int, str] | None`.
- [x] When `notes_by_slide[slide_number]` is a non-empty string, the rendered
  slide section contains a Facilitation block displaying that text.
- [x] When `notes_by_slide` is `None` or has no entry for a slide, no
  Facilitation element appears for that slide.
- [x] Notes text in HTML output is HTML-escaped (characters `<`, `>`, `&` are
  encoded as entities).
- [x] `proof_worksheet.build()` loads `deck_dir / f"{deck_dir.name}-notes.json"`
  if the file exists and passes parsed notes to `render_worksheet()`.
- [x] If the notes.json file is absent, `build()` behaves identically to the
  current behavior (no Facilitation section, no error).
- [x] If the notes.json file is present but malformed (bad JSON), `build()`
  prints a warning to stderr and proceeds without any Facilitation sections —
  no uncaught exception. A test captures stderr and asserts the warning message.
- [x] Per-entry parsing errors (null `slide_number`, non-dict entry) are skipped
  silently; valid entries in the same file are still rendered.
- [x] Two calls to `build()` with the same inputs and notes.json produce
  byte-identical HTML output.
- [x] `proof_worksheet.py` module docstring is updated to reflect that `build()`
  now reads notes.json (when present) and that output determinism depends on
  both planning inputs and the notes.json content.
- [x] All existing `tests/test_proof_worksheet.py` checks continue to pass.

## Assumptions

- Technical: `render_worksheet()` currently has signature
  `(deck_dir: Path, pages: list[dict], as_of: str | None) -> str` (source: probe)
- Technical: `esc()` is the existing HTML-escape helper in proof_worksheet.py (source: proof_worksheet.py:50-51)
- Technical: notes.json schema `{schema_version: "1", slides: [{slide_number, title, notes}]}` (source: html_packager.build_notes_stub probe)
- Technical: Facilitation data comes from the notes.json generated by `planning-notes-generation` spec (source: docs/product/DESIGN.md §Step 4.5)
- Process: spec-driven development; CONVENTIONS.md governs spec metadata (source: docs/CONVENTIONS.md)
